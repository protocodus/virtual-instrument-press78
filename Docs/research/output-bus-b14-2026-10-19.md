# B14: preserve the existing character across host rates

This is an intentional engineering correction to the sound at host rates other than 48 kHz. The established 48 kHz model remains the reference, rather than treating the host sample rate as a property of a physical Yamaha. New and existing documents use the correction in b14; no compatibility property or musical default changes. B13 archives remain available for exact previous non48 behavior.

The existing FM, output circuit surrogate, tone, optional creative Drive, recorded chorus, DC filter, gain and protection now run on the same 48 kHz output timebase. A final stereo converter serves other host rates. At exactly 48 kHz the complete previous engine is delegated directly. All eight full no-pedal performances and the three new preset phrases are byte-identical there. This does not change their prior 48 kHz hardware-comparison scores.

The [engineering audit](host-rate-engineering-audit-2026-10-19.md) identifies unintended differences in the previous filters, chorus interpolation and event-to-output-grid routing. The new bus prevents an event from changing a physical output sample whose timestamp precedes it. It deliberately preserves the underlying 48 kHz engine, including its existing fractional FM clock scheduling; it does not identify or repair unknown OPU silicon timing.

## Conversion and compatibility

The frozen causal sinc converter uses a shared immutable float table, double accumulation, a Kaiser window and a cutoff of 0.95 times the smaller Nyquist. Its half support is `ceil(96/min(1,hostRate/48000))`. Normal host rates were checked through 20 kHz; the lower 8–32 kHz research cases use their explicitly narrower passband. Earlier failed timestamp and table-precision attempts remain in the prototype evidence. Discrete checks are not a continuous-frequency/rate proof.

| Native host rate | B14 declared latency, frames | B13 frames |
|---:|---:|---:|
| 44,100 | 126 | 30 |
| 48,000 | 32 | 32 |
| 88,200 | 236 | 59 |
| 96,000 | 256 | 64 |
| 192,000 | 512 | 128 |

The additional conversion delay is declared to both Rack outputs. The common modeled FM clock can still vary the older 32-tick component slightly; these are nominal values. Reset clears conversion history; all-sound-off clears it immediately while preserving elapsed time. Note releases retain their tails. Null buffers advance time and aliased buffers retain the right channel.

Conversion after a limiter can overshoot its sample bounds. With Output protection enabled, b14 applies a final hard guard only to non48 reconstructed samples outside ±1; in-range samples are unchanged. With protection disabled, unrestricted finite output is unchanged. This is software protection, not a DAC or analog distortion model. In the deliberately extreme 12-voice, maximum-gain, wide-chorus fixture, the raw reconstructed peak reaches 2.169193 and the guard clips it to 1 (maximum alteration 1.169193). Such clipping can create new harmonics. Ordinary preset auditions below do not hit it. The direct 48 kHz path remains unaltered.

## Authentic lo-fi scope

Noise removal does not justify polishing away real hardware coloration. The modeled pitch-command quirks, shared modulation, output filtering, feedback behavior, recorded chorus and clock controls remain intact. No hiss, dither, mains oscillator, random bit errors or arbitrary supply excitation is restored.

The YM3420 nonlinear converter transfer, internal arithmetic precision, BBD bias/level distortion, actual component distributions and voltage-to-audio/clock coupling remain unidentified. The [local sibling supply model](local-supply-model-2026-10-19.md) provides a checked electrical response to explicit source/load changes, not an inferred audio sag amount. Creative Drive and safety clipping cannot substitute for those missing physical transfers. B14 therefore preserves the current character and removes a host dependency without claiming that every requested hardware imperfection has been reproduced.

A later metadata-only correction uses exact binary64 integer ceiling for latency reporting, avoiding a one-frame floating-rounding error at24k (a research rate outside the five native Reason rates). The first design, source snapshots and failed test are retained. A separately frozen rerun preserves every one of the18 native and18 listening WAVs exactly; [the recheck receipt](../../Tests/results/output-b14-audition-recheck.json) binds both attempts. The five Rack latency values above are unchanged by that correction.

The final [Rack validation](../../Tests/results/output-b14-rack-validation.json) passes both native architectures, local/universal builds, all101 patches/four LLVM inputs and36 wrapper groups normally/under ASan/UBSan. Protected Recon14.0.2d7 build20275 passes three creations/native arm64 loads and both CLI suites, with15 protection probes and4900 production files preserved. This does not establish interactive playback, persistence, named patch loading, host CPU or portal delivery acceptance.
