# CPU optimisation, 2026-11-05

Five changes to the engine and the output bus, each its own commit, cut
Press78's CPU on the eight README demos by 15 % at 48 kHz, 7 % at 44.1 kHz and
3 % at 96 kHz in wall time, and by 9-14 % in instructions. Four leave every
output sample bit-identical; the fifth (vibrato and tremolo kernels) changes
only the last bit of some float output samples.

## Method

- **Build.** clang, C++17, `-O3 -fno-builtin` (the Rack's code generation),
  the DSP sources compiled with a harness that plays the committed MIDI in
  `Docs/audio/midi` through `Press78Instrument` with the plug-in's default
  controls (the Real profile), as `RenderPress78PresetDemos` does.
- **Workload.** The eight demos at 44.1, 48 and 96 kHz, 256-frame blocks.
- **Time.** Thread CPU per demo, minimum of three runs, best of three rounds
  alternating baseline and candidate (Intel Xeon, x86-64, Linux, no
  flush-to-zero). Instruction counts from callgrind on three demos, which do
  not depend on machine noise. Development-machine figures, not Reason CPU.
- **Sound.** 128 renders per candidate: the eight demos at the three rates,
  every factory voice on a fixed phrase (chords, melody, sustain, mod wheel,
  bend) at 48 kHz and four voices with Double at 44.1 kHz. Each candidate's
  float output hashes were compared with the previous commit's; where they
  differed the float dumps were nulled.

## Results

Eight demos, % of real time for one instance:

| Host rate | Before (1.0.4) | After (1.0.5) |
| --- | --- | --- |
| 44.1 kHz | 2.58 % | 2.39 % |
| 48 kHz | 1.85 % | 1.57 % |
| 96 kHz | 3.33 % | 3.23 % |

Callgrind instructions, millions:

| Demo | 1.0.4 | 1.0.5 | Change |
| --- | --- | --- | --- |
| 093 Human Chorus, 48 kHz | 2807 | 2552 | −9.1 % |
| 003 Electric Piano 1, 44.1 kHz | 4212 | 3750 | −11.0 % |
| 063 Slap Bass, 96 kHz | 5153 | 4429 | −14.1 % |

Per commit, in order:

| Commit | Change | Sound | Saving (instructions) |
| --- | --- | --- | --- |
| b394e93 | Amplifier clipping curve by series where u^10 < 1e-5 | identical | Human Chorus −6.0 %, Electric Piano −2.9 % |
| 7152f42 | Inline exact `round` for the vibrato delay | identical | Human Chorus −0.2 % (a library call per voice tick in the Rack build) |
| 70353d4 | Vibrato `exp2` and tremolo `dbToGain` kernels | last float bit | Human Chorus −2.0 % |
| d1d7dc1 | Output resampler over contiguous history runs | identical | Electric Piano at 44.1 kHz −7.5 % |
| 6679c3b | Smoothing skipped for controls at their target | identical | −0.8 to −1.1 % |

### Commit 70353d4's difference

117 of the 128 renders differ. The engine's double output moves by a few
ulps; what remains after the conversion to float is single-bit rounding
flips: the worst sample is −142 dB re the render's peak (one 24-bit LSB),
the worst RMS residual −174 dB re the signal.

## Not done

- **Partial sums or SIMD in either resampler** would cut their dependency
  chains, but change the summation order, so no output stays bit-identical.
- **Triangle LFO without `asin`.** The analytic triangle is the exact shape,
  but `asin(sin(x))` near the peaks differs from it by about 1e-8, which
  moves output more than this round allowed.
- **Envelope gain by recurrence** instead of `dbToGain` per tick drifts from
  the per-tick value.
