# CPU optimisation, 2026-10-29

Twelve changes to the engine and the 48 kHz output bus, each its own commit,
cut Press78's CPU in typical playing by 25 % at 48 kHz, 61 % at 44.1 kHz and
68 % at 96 kHz. None is audible: eight leave every output sample
bit-identical, one changes only the sign of exact zeros, and the three that
compute sines and dB gains differently stay at least 178 dB below the signal.

## Method

- **Build.** The Rack's code generation: clang, C++17, `-O3 -fno-builtin`,
  through the real adapter (`Press78.cpp`) and the SDK-free host in
  `Tests/PatchHost.h`. `-fno-builtin` turns `std::abs`, `isfinite`, `floor`,
  `copysign` and `memcpy` into library calls, which several changes avoid.
- **Workload.** Every patch in `Resources/Public` (51) plays the same 6 s
  phrase: a four-note chord, an eight-note melody, a low chord at velocity
  110, a six-note chord under the sustain pedal, then the release tail. A
  variant adds a mod-wheel sweep.
- **Time.** Thread CPU for the whole bank, minimum of three or more runs,
  baseline and candidate on the same machine (Intel Xeon @ 2.10 GHz, x86-64,
  Linux) with nothing else running. Single-patch steps were confirmed with
  callgrind instruction counts, which do not depend on machine noise. These
  are development-machine figures, not Reason CPU.
- **Sound.** Each candidate's per-patch output hashes were compared with the
  previous commit's at 32, 44.1, 48, 88.2 and 96 kHz; where they differed, the
  float dumps were nulled and the worst residual against the signal reported.
  As a floor for that test, perturbing every oscillator sine by one ulp gives
  at most −180.3 dB on all 51 patches.

## Results

Whole bank, % of real time for one instance:

| Host rate | Before (1.0.1) | After (1.0.2) |
| --- | --- | --- |
| 44.1 kHz | 8.52 % | 3.33 % |
| 48 kHz | 3.19 % | 2.40 % |
| 96 kHz | 13.86 % | 4.37 % |

Per commit, in order:

| 04b1d86 | Phase tables at 88.2, 96, 176.4 and 192 kHz | identical | 88.2 kHz 12.0 → 4.9 %, 96 kHz 12.7 → 5.0 % |
| 4301321 | Sinc table's last phase shares the first row | identical | 504 bytes smaller instance |
| 5b87ad0 | Velocity powers computed once per note | identical | sustained pad −23 %, bass −16 % |

| 324de82 | LFO evaluated only by voices that use it | identical | per-voice LFO bass −14.9 %, Init −5 % |
| 50299dd | Inline sines for chorus, LFO and drift | ≤ −182 dB | Init −6.1 %, idle −5 % |

### Idle after a note

The output filters' tails decayed into denormal numbers after the last note.
Without flush-to-zero, an instance that had played one note cost about
52 ms per second of audio from 10 s after it and 185–225 ms/s from 17 s on,
indefinitely; with flush-to-zero, about 8 ms/s. Since 62eb682 each filter
section clears its state once its input is exactly zero and every state is
below `kSettledState` (1e-60, see `FastMath.h`), and the instance returns to
its untouched idle cost, 3.6 ms/s, about 17 s after the note. Whether Reason
runs Rack Extensions with flush-to-zero is not known, so the worst case is the
one without it.

## Not done

- **Silent output buffers.** Leaving Reason's output buffers unwritten while
  the device is silent would let the devices after it idle. The wrapper's host
  contract (`Tests/WrapperHostContract.cpp`) requires both outputs written on
  every batch, and that test needs the Jukebox SDK, so the change is left for
  a session that can run it.
- **Four partial sums in the 48 kHz resampler** gained about 2 % and change
  the summation order, so they were reverted.
